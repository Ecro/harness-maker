## Q-A — Cursor IDE hooks discovery

**Question**: Does Cursor IDE fire hooks defined in `.claude/hooks/hooks.json`,
or does it require a separate `.cursor/hooks.json` with Cursor-native schema?

**Verdict**: ✅ **RESOLVED — Cursor reads `.cursor/hooks.json` (Cursor-native
lowercase camelCase schema). The dual-render is intentional and correct.**

### Evidence chain

1. **kairos `.claude/observability/metrics.jsonl`** — 4 entries, all written
   between `2026-05-07T01:45:07Z` and `2026-05-07T04:12:37Z`:

   ```json
   {"timestamp": "2026-05-07T01:45:07.074993+00:00", "event": "stop", "status": "completed", "loop_count": 0, "duration_ms": null, "model": "claude-opus-4-6", "conversation_id": "fae168d9-..."}
   {"timestamp": "2026-05-07T02:57:54.851736+00:00", "event": "stop", "status": "completed", "loop_count": 0, ...}
   {"timestamp": "2026-05-07T03:29:56.505996+00:00", "event": "stop", "status": "completed", "loop_count": 0, ...}
   {"timestamp": "2026-05-07T04:12:37.068345+00:00", "event": "stop", "status": "completed", "loop_count": 0, ...}
   ```

2. **All 4 entries have `event: "stop"` (lowercase)**. The Claude Code
   `.claude/hooks/hooks.json` template wires telemetry to `PostToolUse` (which
   writes `event: "post_tool_use"` per `src/harness_maker/telemetry.py:53`).
   Cursor's `.cursor/hooks.json` template wires telemetry to `stop`. Lowercase
   `stop` event name is unambiguously the Cursor template's signature.

3. **All 4 entries have `status: "completed"` + `loop_count: 0`**. Per
   `src/harness_maker/telemetry.py:11` docstring:
   > "status/loop_count are unique to Cursor's stop event"

   These are Cursor-only payload fields. Their presence rules out Claude Code
   as the source.

4. **One-entry-per-conversation pattern** (each entry has a distinct
   `conversation_id`). Matches `Stop` semantics (one event at session end), not
   `PostToolUse` semantics (many events per session).

5. **File timeline** (KST → UTC):
   - `metrics.jsonl` last write: `2026-05-07 13:12:37 KST = 04:12:37 UTC`
   - `.cursor/hooks.json` mtime: `2026-05-07 13:22:45 KST = 04:22:45 UTC`
   - `.claude/hooks/hooks.json` mtime: `2026-05-07 13:33:59 KST = 04:33:59 UTC`

   The 4 metric entries were written by **prior versions of the same templates**
   (re-rendered on May 7 13:22-13:33 with the same template). The schema
   continuity holds because we have not changed `templates/cursor/hooks.json.j2`
   structure across recent versions.

### Implication

`templates/cursor/hooks.json.j2` (lowercase camelCase + `version: 1`) is **the
correct Cursor-native schema**, not a stale relic. My initial `/hm:refresh`
proposal P1 framed this as "schema mismatch — delete or rewrite" and that
framing was wrong. The dual-render (`.cursor/hooks.json` lowercase for Cursor;
`.claude/hooks/hooks.json` PascalCase for Claude Code) is by design — each IDE
reads its native format from its dedicated file.

### Open sub-question (non-blocking)

Does Cursor *also* read `.claude/hooks/hooks.json` as a **fallback** when
`.cursor/hooks.json` is absent? Unknown. kairos has both files, so the test
case for fallback-only is not represented here. Resolution would require
deleting `.cursor/hooks.json` from a sandbox and observing whether Cursor
still fires hooks. **This is non-blocking**: the dual-render works empirically;
single-source consolidation is an optional future optimization, not a fix.

## Q-B — Cursor IDE slash command discovery

**Question**: Does Cursor IDE recognize `/hm:*` slash commands defined in
`.claude/commands/hm/*.md`, or does it require `.cursor/commands/hm-*.md`
mirrors?

**Verdict**: ✅ **RESOLVED — Cursor reads `.claude/commands/hm/*.md` natively.
No mirror needed.**

### Evidence chain

1. **kairos `.cursor/` directory contents** (verified 2026-05-08):

   ```
   /home/noel/kairos/.cursor/
   ├── hooks.json
   ├── mcp.json
   └── rules/
       └── harness.mdc
   ```

   No `.cursor/commands/` directory exists. No `hm-*.md` mirrors anywhere
   under `.cursor/`.

2. **kairos `.claude/commands/` exists** with the standard harness-maker
   layout: `.claude/commands/hm/` with `research.md`, `plan.md`, `execute.md`,
   `review.md`, `wrapup.md`, `verify.md`, `loop.md`, `refresh.md`,
   `ai-readiness.md`, etc.

3. **User confirmation (2026-05-08)**: `/hm:*` slash commands worked in Cursor
   IDE for kairos (visible in slash-command picker, executed as expected).
   This is empirical evidence that Cursor read the commands from
   `.claude/commands/hm/*.md` (the only place they exist on disk).

### Implication

- `.cursor/commands/` mirrors are not needed.
- The conditional language in `templates/cursor/rules/harness.mdc.j2`
  ("subject to Phase 1 A4.command-discover verification — if it fails,
  `.cursor/commands/` mirrors will be added") can be replaced with a
  positive statement.
- `_is_cursor_command` dispatch in `render.py:219` is dead code (no template
  feeds it). Phase 3 of the plan removes it per YAGNI.
