## [wiki:pattern] universal-cross-platform-install-prompt | 2026-05-17
README "Universal Bootstrap Prompt" 는 single block — 어떤 LLM agent (Claude Code / Cursor / Codex / 일반 chat) 에 paste 해도 OS (Linux/macOS/Windows native/WSL) 를 LLM 이 직접 감지하고 분기. 핵심 규칙: OS detect 는 `uname -s 2>/dev/null` → 값이 {Linux/Darwin/CYGWIN*/MINGW*} 밖이거나 빈 값/실패면 Windows; WSL 은 `uname -s` 가 Linux AND `/proc/version` 에 "microsoft"/"Microsoft" (case-insensitive) 포함 → POSIX 경로. uv install 은 POSIX 는 `curl -LsSf astral.sh/uv/install.sh | sh`, Windows 는 PowerShell `irm astral.sh/uv/install.ps1 | iex`. ## [wiki:pattern] round-trip-contract-test-floor-plus-equality | 2026-05-17
Whenever harness-maker has a producer/consumer pair where one component writes a JSON-like contract and another reads it (e.g. `ai_readiness.run_structural` → `observability/dashboard.write_dashboard`, `personalization_audit` → dashboard, `_metrics_io` → `security_scanner`), an integration test MUST exercise real producer output flowing into real consumer — not just two unit tests each against a fixture dict matching its own assumption. The required shape (PLAN-health-plugin-bugs-2026-05 ADR-002): (1) build a minimal real fixture project via a reusable `build_min_fixture(tmp_path)` helper that seeds enough signals to clear a pinned `MIN_FIXTURE_SCORE`; (2) call the real producer, get its output; (3) pipe through the real consumer; (4) parse the consumer output back; (5) assert **both** `producer_score >= MIN_FIXTURE_SCORE` (catches fixture rot that would silently zero the score) AND `parsed_score == producer_score` (catches schema drift). Add a paired meta-test that injects the OLD shape by hand and asserts the equality check fires — without that meta-test, the "non-zero" clause is decorative because a degenerate fixture would pass it vacuously. Live example: `tests/integration/test_health_dashboard_roundtrip.py` (2 tests, ~80 LoC). Bug this would have caught: 0.13.0 dashboard renderer silently rendering `Structural score: 0 / 100` for every user (Bug 2 of this PLAN).

## [wiki:convention] metrics-rotation-reader-via-_metrics_io | 2026-05-17
Telemetry files rotate per-day to `metrics-YYYY-MM-DD.jsonl` (ADR-103 in `_metrics_io.py`, shipped 0.7.1). All new rubrics, signals, and audits that inspect `.claude/observability/` MUST use `harness_maker._metrics_io._candidate_files(obs_dir, days=N)` or `iter_recent_entries(obs_dir, days=N, event=...)` — never `Path("metrics.jsonl").is_file()` or a one-shot file open. `_candidate_files` returns matched files newest-first, capped by file count (NOT calendar window — its `days` parameter is a slice cap on the sorted shard list); `iter_recent_entries` yields parsed JSONL entries newest-first within each file. ## [wiki:pattern] harness-yaml-load-via-io-utils | 2026-05-17
Rendered `.claude/harness.yaml` carries a provenance YAML frontmatter block (`generated_by`, `content_hash`, …) injected by `render.py:_format_frontmatter`. The resulting file is a **multi-document YAML stream**, so single-document `yaml.safe_load` rejects it (this was the root cause of the original Second Brain write failure — every CLI call crashed with `yaml.composer.ComposerError: expected a single document in the stream`). All new readers MUST use `harness_maker.io_utils.load_harness_yaml(path)` — it iterates `safe_load_all(text)`, filters out any doc with `generated_by: harness-maker` (so a truncated provenance-only write returns `{}` instead of leaking frontmatter keys as user data), and returns the last non-provenance mapping. The helper also raises `FileNotFoundError` for missing files and surfaces `yaml.YAMLError` for malformed content; callers do their own error translation. Reverse mapper: `interview.answers_from_harness_yaml`. Direct legacy callers tracked for migration in `docs/followups/io-utils-migration.md` (`verify.py`, `worktree.py`); `autoloop_driver.py` + `context_lint.py` handle different file types and are out of scope for ADR-001.

## [wiki:gotcha] second-brain-smart-vault-and-degrade | 2026-05-17
The Second Brain connector now has TWO layered behaviours that look identical from a casual read but are deliberately separated:

1. **Smart vault detection** (`second_brain._validate_vault_existence`, ADR-002): when `vault_path` does not exist on disk, the connector accepts it **iff** `vault_path.parent / '.obsidian'` is a directory — the canonical "create a subfolder of my real Obsidian vault on first write" intent. A path whose parent has no `.obsidian/` raises `SecondBrainError("vault parent is not an Obsidian vault")`. Helper takes `harness_root` so relative `vault_path` values resolve identically to `_vault_root` (fix: same canonical path in check and use; prior to REVIEW-2026-05-17 the two diverged on relative paths).

2. **Graceful degrade** (ADR-008): when `cfg.folders == []` (post-upgrade gap for users who rendered `harness.yaml` before this PR), `_load_config` returns the config cleanly + logs `second_brain.folders is empty — run /hm:configure to add at least one folder`; `search_notes` returns `[]` while emitting the same warning; `write_note` / `append_note` / `patch_note` raise `SecondBrainError(_EMPTY_FOLDERS_REMEDIATION)` whose message points at `/hm:configure`. The constant `_EMPTY_FOLDERS_REMEDIATION` is the single canonical string for this remediation hint — keep it that way.

Auto-mkdir within configured folders (`write_note` line 145: `path.parent.mkdir(parents=True, exist_ok=True)`) is **intentional** (ADR-002 + Round 3 user lock-in) — once a folder is in `cfg.folders`, subdirs under it get created at first write. Do NOT gate this behind a flag without re-opening ADR-002.

## [wiki:pattern] test-fixture-must-mirror-renderer | 2026-05-17
The Second Brain crash went undetected because `tests/unit/test_second_brain.py:_write_harness_yaml` built `harness.yaml` via `yaml.safe_dump(payload)` — a single-document write with no provenance frontmatter. Real renderer output carries the frontmatter (see `[wiki:pattern] harness-yaml-load-via-io-utils`), so the unit suite passed while production was 100% broken. **Pattern**: whenever a fixture writes a file that the production code reads, the fixture must mirror the exact shape the renderer emits — including frontmatter. Defense-in-depth pair: (a) update the unit fixture (`_write_harness_yaml` now injects the frontmatter block, ADR-005), AND (b) add a render-based e2e test (`tests/integration/test_second_brain_e2e.py`) that calls `harness_maker.render.render` LIVE without snapshot-pinning so any future renderer-vs-consumer drift fails in CI. Snapshot-pinning the rendered bytes would defeat this — validator W8 in the PLAN's Plan Validation section spells out why.

## [wiki:gotcha] yaml-key-vs-directory-name-llm-footgun | 2026-05-15
When a YAML config key uses Python snake_case (`work_docs:`) but its value is a hyphenated directory name (`work-docs/`), LLMs reading `harness.yaml` conflate the two and occasionally write artifacts to the non-existent snake_case path. **0.11.6 fix (PLAN-fix-work-docs-naming-footgun)** added a two-layer guardrail with deliberately non-symmetric placement: **Layer 1 (prevention)** is a hard-coded literal warning paragraph injected under `## Outputs` in plan/research/review/wrapup stage templates — the literal must NOT use `{{ config.work_docs.dir }}` Jinja interpolation, otherwise the warning text dissolves when a user customises the dir; **Layer 2 (detection)** is a non-blocking bash probe (`### A1.`) inserted into `verify.md.j2` stage body under a new `## Advisory probes (non-blocking)` section placed AFTER `## The 6 Checks` and BEFORE `## Output`. The probe MUST NOT live inside `verify-before-completion/SKILL.md.j2` — that SKILL's frontmatter description ("Pre-wrapup gate enforcing 6 checks ...") is referenced across 7+ doc sites (SKILL.md.j2 lines 3/9/112, verify.md.j2 lines 3/17/42/142, HOW-IT-WORKS.md, TECH_SPEC.md). Adding a 7th check there breaks the doc-truth invariant. Honest scope: Layer 1 only protects LLMs that load these 4 templates; ad-hoc invocations that skip stage templates bypass Layer 1 entirely and rely on Layer 2's WARN — by design (ADR-003), revisit only if telemetry shows the bypass class recurs. Test pattern for guarding the regression: regex-extract the probe bash block from rendered verify.md and execute against a `tmp_path / "work_docs"` sandbox via `subprocess.run([..."bash", "-c", probe], text=True, timeout=10, check=False)` — asserts exit 0 + WARN on stderr + the migration command `git mv work_docs/* work-docs/ && rmdir work_docs`. Same test asserts the SKILL still has exactly 6 numbered checks (`### 1.` through `### 6.`, no `### 7.`).

## [wiki:architecture] verifier-pass-1-5-reduce-only | 2026-05-11
PLAN-llm-code-review-2026 (ADR-002) defined a verifier role for Pass 1.5 between bug-find Pass 1 and contextual Pass 2 in `/hm:review`. **ADR-008 (2026-05-11)** stripped the auto-invocation surface — the target env has no `ANTHROPIC_API_KEY`, so `AnthropicVerifierClient` + the `verify` CLI subcommand + the stage's Pass 1.5 step were removed; Pass 1 now flows directly to Pass 2. ## [wiki:pattern] jsonl-telemetry-o-append | 2026-05-11
`.claude/observability/review-{YYYY-MM-DD}.jsonl` via `harness_maker.review_telemetry.emit()` uses POSIX `O_APPEND | O_CREAT | O_WRONLY` + looped `os.write` so EINTR-induced short writes don't truncate a JSON line. A `PIPE_BUF (4096)` guard rejects oversized records at write-time AND a `Field(max_length=...)` constraint on the pydantic schema rejects them at construction-time (shift-left). Concurrent reviewers sharing `.worktrees/` serialize at the kernel level for writes ≤ PIPE_BUF — the test fixture exercises 4 threads × 25 records and asserts both `len(lines) == 100` AND `json.dumps(parsed, sort_keys=True) == raw_line` (round-trip equality detects byte-tearing, not just missed records). 15-field schema: `ts, slug, round, pass1_n, verifier_kept_n, verifier_dropped_n, verifier_false_drop_n, verifier_false_keep_n, fixture_label, pass2_kept_n, consensus_passed_n, wall_time_ms, build_break_count, auto_fix_reverted_n, fallback`.

## [wiki:architecture] codex-config-threading | 2026-05-11
`_codex_stage_skills()` and `_codex_target_files()` must receive `config_dump: dict` from `synthesize()` rather than constructing their own `HarnessConfig()` defaults. Without threading, any harness with custom `work_docs.dir`, `default_workflow`, or workflow names silently renders stage skills with wrong embedded values. ## [wiki:architecture] multi-repo-worktree-sibling | 2026-05-09
`sibling_repos` in harness.yaml lists relative paths (no absolute paths — cross-machine portability). `worktree.create` emits one path per line: line 1 = primary WT, lines 2+ = sibling WTs. ## [wiki:architecture] generator-not-runtime-config | 2026-05-09
harness-maker must stay a generator (Jinja2 pre-render), not a pure plugin that reads harness.yaml at runtime. Three file categories are irreducible: (1) hooks.json — IDE-specific schemas (PascalCase vs lowercase camelCase) consumed pre-LLM, no plugin-system injection hook; (2) settings.json — permission sandbox established before LLM runs, cannot be self-set; (3) CLAUDE.md — technically injectable but would break the `<!-- @hm:user:* -->` block-merge contract and content_hash KEEP/REPLACE/MERGE_BLOCK reconciliation that lets user customizations survive upgrades. Agents/skills/commands could be runtime-configured but the complexity delta is not eliminated since the three infra files still need rendering. See ADR-001 in PLAN-plugin-vs-generator-2026-05.

## [wiki:gotcha] worktree-snapshot-harness-path | 2026-05-09

The `ai-readiness.md.j2` template embeds `{{ harness_maker_src_path }}` which resolves to `_HARNESS_MAKER_PKG_ROOT = str(Path(__file__).parent.parent.parent)` — an absolute path. ## [wiki:architecture] per-session-worktree-marker | 2026-05-09
ADR-006: per-session marker files replace the single global `.hm-loop-active`. Pattern: `_write_loop_marker(project_root, primary_wt_name, wt_paths)` writes `.claude/.hm-loop-{primary_wt_name}` (newline-joined absolute paths). `_clear_loop_marker(project_root, wt_name)` deletes only that file. `_detect_existing_worktree` drops the marker-based Signal 1 — each session creates its own WT, no sentinel needed. ## [wiki:pattern] sibling-rollback-on-create-failure | 2026-05-09
`worktree.create()` with sibling repos: if any sibling `git worktree add` fails, rollback all already-created siblings then primary with `contextlib.suppress(RuntimeError)` best-effort cleanup, then re-raise. Pattern: `sibling_wts: list[Path] = []`, append after each successful add, except-block iterates `zip(sibling_wts, siblings[:len(sibling_wts)], strict=False)` then handles primary. `contextlib.suppress` preferred over try/except to satisfy ruff SIM105. Timeout errors (60s) also trigger rollback since `_run()` raises `RuntimeError` for both `CalledProcessError` and `TimeoutExpired`.

## [wiki:pattern] loop-gate-stop-hook-guard | 2026-05-09
The `.hm-loop-active` marker file (placed at git root by `loop.md.j2` step 5, removed before wrapup in step 7) is the signal the `loop_gate.py` Stop hook reads. Key invariants: (1) `stop_hook_active: true` in stdin JSON must be checked BEFORE `_find_marker()` — Claude Code re-fires Stop on every `/stop` attempt, so the guard prevents infinite loop; (2) `.git`-as-file (worktree `gitdir:` pointer) counts as a git boundary — walk stops on both `Path.is_dir()` and `Path.exists()` for `.git`; (3) Cursor has no Stop event equivalent — PreToolUse advisory only, always exits 0; (4) Step 7 deletes the marker FIRST, before wrapup, so a wrapup crash cannot leave a stale marker that blocks future sessions.

## [wiki:pattern] loop-4gate-convergence | 2026-05-10
`/hm:loop` convergence uses 4 independent gates instead of a single LLM judgment: Gate 1 (Mechanical — run `ExitCriterion.cmd` items, skip `cmd=""`; `required:false` = warning only), Gate 2 (LLM individual — evaluate each criterion label independently; deadlock detector increments `criterion_ambiguity_counts[label]` on "Ambiguous", triggers `AskUserQuestion` at count 3), Gate 3 (Regression — compare exit-code + set of failing test names vs `runtime.last_test_result` baseline; skip on iter 1), Gate 4 (Streak — single reset site, increment on all-pass, reset to 0 on any fail, converged at ≥ 2). All four ephemeral counters (`convergence_streak`, `checklist_fail_counts`, `criterion_ambiguity_counts`, `last_test_result`) persist to the `runtime:` block of the loop-context YAML so they survive `/compact`. Recovery instruction lives in loop.md.j2 step 6. The checklist gate (step 7) fires BEFORE marker deletion so re-entry cycles remain under the Stop hook guard.

## [wiki:pattern] make-ux-gaps-7phase-lifecycle | 2026-05-10
`/harness-maker:make` now covers the full lifecycle: install (smart defaults + confirm), update (`/hm:make`), configure (`/hm:configure` — targeted dimension overrides), preview (`--dry-run`), profile (`harness-maker profile`), and remove (`harness-maker remove` + `/hm:uninstall`). The `_apply_dimension_overrides` function preserves unspecified fields via `model_copy(update=...)` — partial overrides (e.g. `--grade-threshold B`) never reset other dimensions. The `remove` subcommand reads `.harness-manifest.json` (authoritative file list written at make time) so it can delete frontmatter-less files (`settings.json`, `hooks/hooks.json`). Files with `@hm:user:` blocks are skipped with a warning (ADR-007). `harness.yaml` is kept by default (`--remove-yaml` to delete).

## [wiki:pattern] deep-interview-gate | 2026-05-10
The 3-Layer Deep Interview Gate is a post-interview quality gate added to spec/plan/research/loop stages. Layer 1 — GCIC Gap Check: map prior answers to 4 axes (Goals / Constraints / Inputs / Context, 0.0/0.5/1.0), apply CLARITI filter (Task Relevance AND User Answerability ≥ 0.7) to uncovered axes below 0.7, log others as "LLM-inferred". Layer 2 — Implicit Probing: 5 stable labeled candidate types (spec/plan/loop: WRONG/METHOD/STAKEHOLDER/STYLE/PERF; research: NOT-USEFUL/AVOID/DEPTH/AUDIENCE/TIME-SCOPE), MUST NOT reuse a type label from prior rounds, batch ≤4 into one `AskUserQuestion`. Layer 3 — Ambiguity Score: `G×40% + C×30% + SC×30%` (research uses OC not SC), 2 consecutive PASS rounds → converge, max 3 NEEDS rounds. Score monotonicity rule: drop ≥ 0.1 requires `[score-drop-reason]: ...` note appended to the display block before applying the drop. Skip guards: gate fires only when the user has NOT already signaled "clear/skip" in the preceding round. Escape hatch at 3 NEEDS: named options (A: proceed / B: refine) rather than prose question.

## [wiki:pattern] dict-tuple-paren-trap-prevention | 2026-05-11
Dict values written as `"key": ("string a " "string b")` are implicit-concat strings, but the parentheses are visually indistinguishable from a one-element tuple with a missing trailing comma. Adding `, "extra"` silently turns the value into a tuple — exactly how the original `dict[str, tuple[str, str]]` Codex bug crept in. When a dict's value type is `str`, prefer plain single-line string literals (with line-length suppression for long descriptions) over parenthesized multi-line concat. The `# noqa:` directive must live on a code line, not inside a `#` doc comment — ruff parses `# noqa:` inside comments and warns about unknown rule codes, so reference line-length suppression by paraphrase in docs.

## [wiki:gotcha] expanduser-must-precede-join | 2026-05-13
`Path.expanduser()` only expands `~` when it appears at **position 0** of the path string. `Path("/root") / "~/foo"` produces `Path("/root/~/foo")`, then `.expanduser()` is a silent no-op because `~` is at index 8, not 0. Bug pattern in `refdocs_index._build_block`: `(harness_root / rf.path).expanduser().resolve()` — when `rf.path = "~/foo"`, the resolved path was `<harness_root>/~/foo`, a non-existent directory. Fix: expand `~` BEFORE joining, then conditionally join only when the result is still relative. Canonical pattern: `raw = Path(p).expanduser(); abs_root = raw.resolve() if raw.is_absolute() else (root / raw).resolve()`. `second_brain.py` got this right (`Path(cfg.vault_path).expanduser()` — no prior join). The downstream consumer of any `~`-relative path stored by `denormalize_home_to_tilde` (see [[bash-tilde-expansion-on-var-assignment]]) MUST follow this expand-before-join rule.

## [wiki:gotcha] bash-tilde-expansion-on-var-assignment | 2026-05-13

Claude Code's slash-command bash construction tends to write the unquoted form, so paths typed as `~/edge_bsp_foundation` reach the CLI as `/home/alice/edge_bsp_foundation`. Storing that absolute path in `harness.yaml` breaks team sharing — teammate Bob has `/home/bob`, not `/home/alice`. Fix lives at the CLI boundary: `io_utils.denormalize_home_to_tilde()` re-prefixes `$HOME`-rooted absolute paths with `~`. Downstream consumers call `Path(...).expanduser()` so the `~/...` form still resolves correctly on every machine.

### [wiki:gotcha] readme-one-prompt-bash-not-slash | 2026-05-19

## [wiki:gotcha] pipestatus-vs-dollar-question-mark | 2026-05-19
Workflow scripts that pipe a fallible command through `tee` (for log capture) and then check `$?` are silently broken — `$?` reflects the rightmost pipeline command (tee), which exits 0 on any successful disk write regardless of the upstream's outcome. Use `${PIPESTATUS[0]}` to grab the first stage's exit code, OR add `set -o pipefail`. Discovered in `release.yml` `boundary-advisory` job (REVIEW-test-fidelity-gap consensus-passed P1): pytest could fail every release and the advisory status label still wrote ✅ PASS. ## [wiki:gotcha] cwd-shifts-across-bash-calls | 2026-05-20
A worktree is a real git path on disk (`.worktrees/<name>/`), and when Claude Code's shell starts inside it (e.g. after `/hm:loop` engaged the worktree), every subsequent `!`/Bash call inherits that cwd unless the command explicitly `cd /path/to/main &&` prefixes. Symptom: ruff / mypy / pytest / git report state inconsistent with what the Edit tool just wrote — because Edit resolved an absolute path on main while the linter ran against the worktree copy. Diagnose with `readlink -f tests/unit/<file>` and `pwd`. Fix: prefix every wrapup-stage Bash with `cd /home/noel/<project> && ...` once the merge has happened, OR exit the worktree directory before invoking wrapup. The Edit tool itself does NOT inherit cwd (uses absolute paths in tool inputs), so the divergence is silent until a tool that DOES inherit cwd (Bash, pytest discovery, ruff path globs) reads the worktree copy and reports stale findings. Pattern: when a tool-call output disagrees with the Read/Edit content for the same path, **first check pwd before debugging the file**.

## [wiki:pattern] mutmut-stale-cache-on-test-changes | 2026-05-20
`mutmut 2.5.1` aggressively caches per-mutant verdicts in `.mutmut-cache` across runs. When the test suite changes (e.g., new mutation-killing tests added), previously-surveyed mutants are NOT automatically re-tested — they retain their old verdict. Symptom: `mutmut results` reports a mutant as `Survived 🙁` even when the new tests clearly catch it (manually verified via `mutmut apply <id>` + `pytest -x`). Workaround: force a specific re-test with `mutmut run <mutant_id> --paths-to-mutate=<path> --runner=<cmd>` to invalidate just that mutant's cached verdict. For a definitive baseline after substantial test additions, delete `.mutmut-cache` and re-run full mutmut. Discovered while pushing cache.py kill rate from 3.8% → 98.08%; mutant 42 (`path = None` in `invalidate`) initially survived in the cache despite a test that catches it (`test_invalidate_removes_existing_entry`). Document this in any mutmut-driven gate's runbook so reviewers don't chase ghost "real bug not killed" failures.

## [wiki:pattern] equivalent-mutants-typing-cast-runtime-noop | 2026-05-20
`typing.cast("X", value)` is a runtime no-op — its first argument is a string used only by static type checkers. mutmut will happily mutate the string (e.g., `cast("T", x)` → `cast("XXTXX", x)`), and these mutants can NEVER be killed by runtime tests because the value is returned unchanged regardless. These are textbook "equivalent mutants" and should be documented + excluded, not pursued. Same class: integer-default-of-`data.get(key, 0)` → `data.get(key, 1)` when the value is later subtracted from `time.time()` (~1.7×10⁹) — the 0 vs 1 difference is numerically indistinguishable for any realistic ttl. For any mutation baseline with surviving mutants, classify each as `equivalent_mutant` (semantic no-op) or `real_mutant_not_killed` (test gap) in the baseline JSON before claiming low kill rate is a real coverage problem.

## [wiki:gotcha] python-isdigit-accepts-unicode-numerics | 2026-05-21

## [wiki:pattern] content-gated-orphan-branch-sweep | 2026-05-31
`prune_stale` (runs at every `worktree create`) now sweeps leaked `execute-*`/`plan-*`/`phase-*`/`autoloop-*` branches whose worktree dir is gone — closing the orphan-branch leak (`cleanup()` deliberately never runs `git branch -D`, to keep the `wip(execute)` recovery net alive while a worktree is live, so finalized branches leaked forever). The sweep is **content-gated, biased-to-preserve**: `_branch_content_in_head(base, branch)` returns True only when every blob the branch changed since its merge-base with HEAD is byte-identical in HEAD; any unresolvable ref / missing / mismatched blob → False → preserve+warn (never delete unsaved work). It mirrors `_stash_content_in_head` and **must NOT use `git branch --merged`** — a squash-merged tip is not a HEAD ancestor, so `--merged` would wrongly report it unmerged and miss it. Cross-session safety falls out for free: an in-flight session's stage-only-finalize branch (work staged, not yet committed by wrapup) is NOT in HEAD → preserved; once its wrapup commits, a later prune sweeps it. Live-skip keys on `_registered_worktree_paths` (ADR-002), not just `dir.exists()`. There is no `S^3` untracked-tree leg (unlike the stash predicate) because a branch has no untracked tree — untracked work was already captured into the `wip(execute)` commit. General principle worth carrying to any destructive cleanup of maybe-unsaved work: gate the delete on "content already preserved", default to preserve on ambiguity. See PLAN-p6-p7-worktree-finalize ADR-002; related [fail:design] worktree-finalize-pulls-orphan-wip-into-main.

## [wiki:pattern] merge-fence-wraps-full-critical-section | 2026-06-01
PLAN-p6-p7-worktree-finalize P2 (ADR-003) widened the Layer-4 merge fence in `_cli_finalize` to wrap **exactly** `{_stash_base_dirty, _snapshot_staged_paths, merge}` instead of only `merge()`. The bug it closed: `_stash_base_dirty` (`git stash push -u`) ran OUTSIDE the fence, so two parallel finalizes could stash the same base concurrently — the race the fence exists to prevent. Invariants that make the widening safe: (1) `staged_before` snapshot captured STRICTLY AFTER the stash (the scope-guard's `--allow-dirty-base` exemption reads the post-stash index — a load-bearing order; extracted to a named `_snapshot_staged_paths` so a test can pin it); (2) `_capture_pending_in_worktree` stays OUTSIDE the fence — it's worktree-side (per-worktree index), not base-side, so fencing it would only inflate hold-time; (3) `handed_off`/`_write_stash_ref_file`/`cleanup`/both pop paths stay OUTSIDE/after the fence (pop-inside-fence would be wrong); (4) `handed_off` computed AFTER the fence, inside the `if wt_rc==0` block, init `False` before the outer try so the rollback `finally` always has a value. **Timeout (CN1, supersedes ADR-003's original "keep 60s"):** because the fenced section now HOLDS the lock for up to `_GIT_TIMEOUT_LONG` (stash, 300s) + `_GIT_TIMEOUT` (merge, 60s), the *acquire* timeout was raised to `_FENCE_TIMEOUT = 360s` so a legitimately-slow first finalize doesn't spuriously TimeoutError a parallel second one. The P2 review left it at 60s as an ADR-003 watch-item; the follow-up CN1 raised it. **Pops fenced too (CN2, supersedes ADR-003's "pops stay outside the fence"):** both base-stash pops route through `_fenced_restore_base_dirty` (fence-wrapped `_restore_base_dirty` with an UNFENCED fallback on fence-acquire failure) so two parallel finalizes don't race the shared stash/`index.lock`. **Accepted narrow downside:** raising the acquire budget to 360s lengthens the O_EXCL *secondary* path's stale-lock stall if a holder is SIGKILL'd (flock — the WSL2 primary — auto-releases on death, so unaffected); self-heals via the unfenced fallback, no hang. A proper fix (mtime/PID staleness guard on `_excl_lock`) is a separate, TOCTOU-careful fence-primitive hardening, deliberately NOT rushed. General concurrency principle: **a lock must wrap the full critical section including its slow setup op, AND the acquire-timeout should exceed the worst-case hold** — widening one without the other trades a race for a spurious-timeout. Related [wiki:pattern] content-gated-orphan-branch-sweep (P1, same PLAN).

## [wiki:pattern] fail-safe-direction-when-unifying-divergent-parsers | 2026-06-01
PLAN-p6-p7-worktree-finalize P3 collapsed 3 divergent inline `git status --porcelain` parses into one `_porcelain_path` helper. Two of the 3 consumers (`_is_harness_artifact`, `_is_create_guard_harness_artifact`) FEED the Layer-2 dirty-base guard — they decide harness-churn (ignore) vs user-dirt (block create / stash before squash). The old copies differed in quote-stripping (`.strip('"')` vs `[1:-1]`-if-wrapped) and rename handling. The review heuristic that cleared the unification: **don't just ask "are they equivalent?" — ask "in the direction they CAN diverge, is the divergence fail-safe for the safety consumer?"** Here the new `[1:-1]` strips ≤ the old `.strip('"')`, so any divergence yields a path LESS likely to match a harness prefix → MORE lines classified as user-dirt → the guard fires MORE, never less → no contamination/data-loss regression (and `_stash_base_dirty` stashes more, not less). For real git porcelain the two are identical anyway (git quotes once, escapes interior quotes), so the divergence is theoretical — but proving the *direction* is fail-safe is what makes a parser-unification touching a safety gate reviewable as safe rather than just "looks equivalent." Companion polish in the same phase: batch N `git check-ignore` subprocesses into ONE `--stdin` call (read paths from stdin, parse the ignored subset from stdout) — but only safe because no churn pattern subsumes another, so the batch's read-once design can't diverge from the old append-one-at-a-time loop's intra-run subsumption.

## [wiki:gotcha] subagent-tools-field-hard-gates-bash-permission | 2026-06-02
In a Claude Code subagent, the `tools:` frontmatter is the HARD gate on tool *availability*; `permissions.allow`/`deny` only scope *which commands* run once a tool is available. So `permissions.allow: Bash(codex exec:*)` is **completely inert** when `tools:` omits `Bash` — the agent has no Bash tool at all. This silently broke `codex_second_opinion` on `code-reviewer` / `consensus-arbiter` / `plan-validator` (all `tools: Read, Grep, Glob`): the second opinion skipped with "validator env had no Bash" while the permission *looked* granted. The same trap had silently disabled `code-reviewer`'s `Bash(git diff:*)` / `git log` / `git status` allow-entries — they were unreachable for the same reason. Fix: add bare `Bash` to `tools:` (the field takes only bare tool names — it CANNOT argument-scope, so `Bash(codex exec:*)` is meaningless there; scoping stays in `permissions`). **Diagnostic to grep for: any agent with a `Bash(...)` entry in `permissions.allow` but no `Bash` token on its `tools:` line has an inert permission.** Granting bare Bash is safe only when the deny list is complete — keep the REVIEW-M7 interpreter quartet `Bash(python:*)`/`Bash(node:*)`/`Bash(sh:*)`/`Bash(bash:*)` (+ rm/curl/npm/eval), since with Bash available the deny list becomes the sole barrier and `Bash(sh -c "...")` would otherwise bypass rm/curl blocks. Cross-ref PLAN-spoton-codex-rm-stash-rootcause ADR-001.
