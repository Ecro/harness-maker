## [decision:multi-repo-mgmt-2026-05] ADR-006: per-session marker replaces global .hm-loop-active | stage:wrapup

The single `.hm-loop-active` file prevents parallel sessions from each protecting their own worktree. Per-session `.hm-loop-{wt_name}` files allow N concurrent sessions without coordination. `_detect_existing_worktree` removes the marker-based signal entirely — path-based detection is sufficient since each session gets its own WT name. The gate (Phase 3, deferred) will glob `.claude/.hm-loop-*` and union all paths. Non-obvious constraint: marker must be KEPT on `finalize fail` status so the gate continues to protect surviving worktrees; only cleared when ALL repos succeed.

## [decision:multi-repo-mgmt-2026-05] worktree.create() returns list[Path] — backward compat by [0] indexing | stage:wrapup

Return type widened from `Path` to `list[Path]`. All single-repo callers append `[0]` — this is the stable contract. Sibling callers receive `[primary_wt, *sibling_wts]` in the same order as `sibling_repos` in harness.yaml. The review found that the e2e test missed the `[0]` update — rule: when changing return type from scalar to container, grep ALL callers including e2e test files.

## [decision:how-it-works-docs] exec-rev-wrap wrapup behavior | 10:00 UTC | stage:wrapup

Initially documented that wrapup skips on grade miss (D/F). Correct behavior: wrapup always runs; on grade miss it sets `human_review_needed=true` and proceeds. The flag is the signal — not a hard stop. This is the "autoloop policy" so the loop can always close cleanly regardless of review outcome.

## [decision:plugin-vs-generator-2026-05] --update flag is a CLI-layer alias, not a new engine path | stage:wrapup

The key trade-off in ADR-001: rendering is irreducible for three file categories (hooks.json schema divergence, settings.json pre-LLM sandbox, CLAUDE.md customization contract). The `--update` flag does not introduce a new code path — it gives the existing `answers_from_harness_yaml() → synthesize() → reconcile() → render()` path a name and makes the contract explicit. The prior friction was that users couldn't tell "will this trigger an interview?" — the flag resolves that uncertainty. SessionStart drift detection was already wired; the gap was only the named command to run.

## [decision:multi-repo-mgmt-2026-05] Phases 3-9 snapshot regen must run in main repo, not worktree | stage:wrapup
Snapshot tests compare SHA-256 of rendered template output, which includes `harness_maker_src_path = Path(__file__).parent.parent.parent`. When snapshot regeneration ran inside a worktree (`.worktrees/execute-YYYYTHHMMZ`), the embedded path was the worktree path, not the repo root. This caused snapshot mismatches when tests ran outside the worktree. Fix: always run `tests/snapshot/regenerate.py` from the main repo root, never from a worktree. The snapshot tests themselves run correctly regardless of cwd since they use `Path(__file__)` from their location in `tests/unit/`.

## [decision:loop-longevity-review] loop_gate.py uses cwd not workspace payload path | stage:wrapup

Security reviewer (MO-1, manual-only) flagged that `_stop_hook()` calls `_find_marker()` with no `start_dir`, so it defaults to `Path.cwd()`. Claude Code hooks run in the project root context, so this works in practice — but it would silently miss a marker if hook process cwd ever differed from the workspace root (multi-project hosts, symlinked repos). Not auto-fixed because single-source finding and low immediate risk. Future hardening: parse `workspace` field from Stop hook stdin JSON and pass as `start_dir` to `_find_marker()`. Deferred to next iteration when there is evidence of real cwd drift.
