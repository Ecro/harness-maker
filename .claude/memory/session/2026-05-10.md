## [decision:deep-interview-gate] skip-guard placement is the load-bearing UX contract | stage:wrapup
The 3-layer gate's key architectural decision was that skip guards must be evaluated FIRST in each gate instance — before any GCIC scoring — and must honor signals from EARLIER rounds in the SAME session, not just the current round. The UX review caught that a user who signals "SPEC is sufficiently clear" in §2.1 round 1 should never encounter the gate in §2.5 at all. This is fundamentally different from convergence logic (which cares about consecutive rounds); the skip guard is a session-level one-way latch. Second key decision: Layer 2 type labels must be stable identifiers (WRONG/METHOD/STAKEHOLDER/STYLE/PERF) rather than semantic descriptions, because LLM "MUST NOT ask the same type" needs an exact-match rule it can enforce reliably over possibly-compacted context. Score monotonicity rule required explicit output target (`[score-drop-reason]: ...` appended to Layer 3 display block) or else LLM has nowhere to write the note and may silently skip or block.
