## [decision:worktree-cross-session-data-loss-defense] 5-layer defense + dirname-embed substantive fix shipped | 16:30 UTC | stage:wrapup

PLAN-worktree-cross-session-data-loss-defense shipped — 3rd recurrence of `[fail:design] worktree-finalize-pulls-orphan-wip-into-main` closed. **Key non-obvious decision sequence:** (1) original ADR-004 said "session-id namespace", I implemented as project-scoped persistent file `_current_session_uuid` → REVIEW round 1 P0-MAN2 catch: that helper returns SAME uuid for every session on same project → Layer 3 isolation never actually fires. Test fixture passed because it never seeded the file (subprocess generated fresh UUID → didn't match either ref → both stashes "skipped" but for the wrong reason). (2) substantive fix: dirname-embed UUID per the original ADR-004 §2 — `execute-{12hex}-{ts}`. `_extract_uuid_from_wt_name` parser, `create()` generates UUID inline, `_write_stash_ref_file` reads UUID from `wt_name` arg (NOT from project-shared file). (3) post-commit-pop's ownership inference is HARD without explicit owner-list: filesystem state (`.hm-loop-*` markers) is shared across all sessions on the same disk — same flaw as the original `_session_marker_present` check. Decided strict mode via `HM_OWNED_SESSION_UUIDS` env var; wrapup template must SET it (task #14 follow-up). Without env, degrades gracefully to old marker-exists check (= pre-Phase-3 vulnerable behavior). (4) `_acquire_merge_fence` lock_dir: REVIEW P0-MAN1 catch — naive `(base / ".git").is_dir()` returns False on worktrees (`.git` is FILE there) → per-worktree lockfile → no serialization. Fix: `git rev-parse --git-common-dir` resolves shared gitdir; all worktrees of same repo share one lockfile. (5) `.claude/` is fully gitignored at user repos so `_is_create_guard_harness_artifact` uses a SEPARATE filter from `_is_harness_artifact` (which finalize-stash uses to decide what to capture); narrowed scope keeps finalize-stash preserving real user edits in `.claude/`. (6) bypass flags `--allow-stash-queue` + `--allow-dirty-base` always log `[WARN]` to stderr so post-incident forensics distinguish "guard fired and was bypassed" from "guard never fired" — addresses REVIEW P1-MAN4. **Permanent lesson:** when designing cross-session isolation, the source of "who owns this state" must be EXPLICIT (env var passed by parent, dirname embed, etc.) — filesystem-shared markers can't distinguish OWN from OTHER without convention enforcement upstream.
