## [decision:locate-cli-version-gate] Ship `locate` CLI + `--require-version` flag + canonical BOOTSTRAP.md | 14:50 UTC | stage:wrapup

PLAN-locate-cli-version-gate shipped 0.20.0. Fixed the fresh-install footgun where bootstrap meta-prompts re-implemented plugin-cache resolution and silently picked stale versions (e.g. kairos@0.7.3 via `entries[0]` fallback in hwcc bootstrap on 2026-05-21). Three architectural decisions locked in interview:
- ADR-001: `locate` JSON default + `--plain` for installPath only (NOT bash-first; agent consumers are the harder consumer and get the default)
- ADR-002: `--require-version` is a flag on existing `make` + `locate`, NOT a new top-level `check` subcommand (keep CLI surface small)
- ADR-003: canonical bootstrap pattern lives in `docs/BOOTSTRAP.md`, NOT a `/hm:bootstrap` slash (slash commands are post-install — can't solve chicken-and-egg)

Strict 3-tier priority: `projectPath == cwd` > `scope == "user"` > `installedAt` desc tiebreak. Deliberately NO tier-3 fallback to "most-recent project-scope of another project" — that would re-introduce the entries[0] footgun in a different form.
