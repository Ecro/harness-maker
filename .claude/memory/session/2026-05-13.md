## [decision:sessionstart-systemmessage] Drift hook must emit systemMessage for visibility | 14:30 UTC | stage:wrapup
User reported the SessionStart drift hook "doesn't tell me anything" despite emitting valid `additionalContext`. Confirmed via Claude Code spec: `additionalContext` feeds Claude's internal context only — invisible to the user. `systemMessage` is the user-facing channel. Non-obvious because the JSON output looked correct in manual hook tests; the bug was in the rendering contract, not the code path.

## [decision:install-ref-file-url-detection] file:// URL beats editable flag for local-install detection | 14:30 UTC | stage:wrapup
Original `_compute_install_ref()` returned local path only when `dir_info.editable=True`. But Claude Code's `/plugin install` produces `editable=false` + `url=file:///...` (plugin cache). Every drift hook in every `/plugin install`-ed project silently failed `uv run --with harness-maker` (not on PyPI). Revised rule: check `url.startswith("file://")` — covers editable dev tree AND non-editable plugin cache. Parse-failure fallback flipped to local path too (safer ambiguity resolution). ADR-002 amendment.

## [decision:tilde-denormalize-at-cli-boundary] Reverse bash $HOME expansion in CLI parsing | 14:30 UTC | stage:wrapup
Bash expands unquoted `~/foo` to `/home/alice/foo` at variable assignment time. Claude Code's slash-command bash construction tends to write unquoted, so paths typed as `~/edge_bsp_foundation` reach the CLI as absolute paths — stored in harness.yaml, they break team sharing across different home dirs. Fix at CLI boundary (`io_utils.denormalize_home_to_tilde`) instead of guessing where in the Python code the expansion happened (it didn't — the shell did it before Python). Applied to `--ref-folders`, `--second-brain-vault-path`, and interview `_ask_ref_folders` / `_ask_second_brain`.
