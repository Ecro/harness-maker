# Session log — 2026-05-30

## [decision:spec-test-forward-binding] ship execute↔machine.yaml forward binding (0.28.0) | stage:wrapup

Shipped PLAN-spec-test-accumulation: `/hm:execute` now consumes `SPEC-{slug}.machine.yaml` so spec↔test bindings accumulate forward instead of being reverse-mapped by the backfill loop. Non-obvious decisions and surprises:

- **Write-back location was the binding architectural call.** plan-validator's first pass (MAJOR_REVISION) found that an in-worktree write-back fails cross_validate (collection cwd `md_path.parent.parent` = base, but the authored test lives only in the worktree until finalize) AND races the 5-layer cross-session worktree defense (machine.yaml is a committed deliverable, not churn-gitignored). Both criticals collapse if the write-back runs in `/hm:wrapup` in the BASE repo AFTER finalize — chosen over serialize-in-worktree / line-stable-merge. ADR-005.

- **`executable_predicate` was prose, so "predicate-bound" was hollow.** Validator C2: `spec_machine.validate` only checked non-empty. Tightened to require `ast.parse(mode="eval")` → assertable node (Compare/Call/BoolOp/UnaryOp) + ≥1 Name. Honest residual limitation: `"fast and reliable"` parses as `Name and Name` (BoolOp) and slips through — documented, test-reviewer is the semantic backstop. ADR-007. Back-compat waived (ADR-008): no CI gate runs validate over the real 83 placeholder specs, so this PLAN's suite is unaffected; their migration is a follow-up.

- **Two latent dead-CLI bugs found mid-execute.** `spec_machine` and `spec_mutation` had NO `__main__` — the pre-existing `spec.md.j2` `python -m harness_maker.spec_machine validate` call was already dead. Added argparse CLIs so both the new instructions and the old one are real. Lesson now in wiki: a template instruction invoking `python -m X` requires X to actually have that CLI.

- **The real catch: a mock-only test hid a broken rule-3.** `_check_pytest_collect` ran `--collect-only` without `-q` → tree output with no `::` nodeids → every test_id reported unresolved → rule-3 silently broken in all real use, green only because every test mocked the helper. Surfaced when `mark_tested` exercised it for real. Fixed (`-q` + rc-aware degrade) + an UNMOCKED lifecycle test. Recorded as `[fail:test] mock-only-helper-hides-external-tool-format-bug`.

- **Review (Grade A) still earned its keep.** Single reviewer per domain → all findings formally `manual-only`, but 3 were genuinely valid and fixed rather than shipped: security argv-injection (`test_id` tokens spliced into pytest argv unfenced — same trust boundary the project already guards for `paths_to_mutate`; asymmetric gap), write-before-validate, and pytest-absent false-flagging in spec_drift. Each got a regression test.

- **Mechanical-first leaves an intentional half-state.** parametric/judgment ACs stay `pending_test` until a follow-up PLAN; `evaluate_coverage` counts pending as covered, so the wrapup per-type coverage report + the spec_drift resolved-but-pending detector (ADR-009) exist to keep the gap visible, not silent.
