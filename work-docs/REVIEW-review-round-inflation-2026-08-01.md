## ✅ Consensus Findings

### A — The stage's numbered loop contradicts the §5 order it points at · **P1** · `consensus-passed` [2/3]

`code-reviewer` (review.md.j2:517) + `codex` (SKILL.md.j2:167) — the two ends of one contradiction,
same tier, CONCLUDE aligned.

`review.md.j2:511-513` says "Evaluate the trigger **before** selecting fixes", but the numbered
list immediately below runs `1. Select fixable findings → 2. Group first (trigger) → 3. Verify →
4. Re-review`. §5 pins the opposite: verify → re-review → merge → stamp → determine `caused_by` →
group/trigger → select → apply. **`caused_by` is never determined anywhere in the stage's
numbered procedure** — it appears only in step 6's record table, after apply.

Reproduced: `grep` over the rendered loop confirms the ordering and the absence.

This is ADR-012's original defect, re-created one level up: each document is coherent alone, and
the contradiction only exists between them. `code-reviewer` added a consequence `codex` did not
see — under the stage's order the round's fixes **are** re-reviewed at step 4, so
`unreviewed_fix_count` is 0 by construction and the counter reports a constant.

**FIXED (round 3), after the escalation was decided.** The stage's numbered loop is now
`1. Merge and attribute → 2. Group → 3. Select → 4. Apply → 5. Verify → 6. Re-review →
7. Grade → 7b. progress → 8. Record → 9. Gate`, and §5 states the same order. Attribution
precedes the trigger, so arm (b) is reachable; verify and re-review stay in-round, so a build
break is still reverted immediately. ADR-012 and ADR-004 were amended in the PLAN — see the
resolved Blocker below.

The order test was rewritten to assert the **numbering** rather than the sentence that used to
claim it. The prose clause "Evaluate the trigger before selecting fixes" is deleted: prose
drifting from the numbered list is what created this finding, so a gate reading prose had no
reason to exist.

**FIXED (round 2)** — the Telemetry Emit block now states the rule literally: `terminal: false`

round the loop exits at; never 0 for an unmeasured value.

## ✅ Blocker — RESOLVED (was: finding A needs an ADR decision, not an auto-fix)

**Decision taken:** keep the apply-first order and re-define the counter. Adopted because a build
break reverted in-round is worth more than what apply-last bought, and because the counter is
recoverable by definition whereas build safety is not. ADR-012 rule 1 and ADR-004 amended in the
PLAN with the trade-off table and the reason each alternative was rejected.

`unreviewed_fix_count` now counts **applied fixes whose file no re-spawned reviewer covers**,
summed over the run — a real, non-zero quantity, because selective re-review deliberately
re-spawns only the reviewers whose scope the fixes touched. The old definition ("the terminal
round's fixes") was 0 by construction under this order.

The original escalation stands as recorded:

The two candidate orders are not interchangeable and each breaks something the other preserves:

| | §5 / ADR-012 order (apply last) | Current stage order (apply first) |
|---|---|---|
| Build safety | A break survives to the next round | Caught and reverted in-round |
| `unreviewed_fix_count` | Non-zero — the terminal round's fixes are genuinely unreviewed | **0 by construction** — step 4 re-reviews them |
| arm (b) reachable | Yes | No — `caused_by` is never determined |

Making arm (b) reachable is unambiguous and can be done under either order. Choosing where
`verify` sits is an ADR-012 amendment, and the counter's definition follows from it. Applying
either silently would contradict a binding ADR, which the execute contract forbids.
