# AUDIT — Cross-Model (Codex) Gaps & Improvements

**Date:** 2026-06-07
**Origin:** External analysis run from a separate "vault" Claude-Code session that built a `codex-duel` skill (PIDA cross-model debate) and wired it into its own `/review` + `/myplan`. This doc carries the *harness-maker-side* findings over for action in a harness-maker session.
**Method:** 3-way reconciliation — Claude analysis + a read-only Explore pass over `src/harness_maker/` and `.claude/skills/` + an **independent Codex (GPT-5.4-codex) pass** (Route Q answer-duel). Codex materially corrected the initial premise (see below) and contributed two findings Claude missed (H4, H5).

> ⚠️ **Premise correction (by Codex):** harness-maker is **NOT** "entirely single-model." It already has a real, tested, schema-strict Codex second-opinion integration (`CodexSecondOpinionConfig`, `second_opinion_codex.md.j2`, `codex-finding.schema.json`, `PLAN-codex-*` work-docs). The gaps below are about **protocol depth, learning, scope, and operational safety** — not about adding Codex from scratch.

---

## What harness-maker already does well (keep — do not regress)

- **Strict output schema** — `.claude/schemas/codex-finding.schema.json` (draft-07, `additionalProperties:false`, severity enum). Forces Codex into structured findings; avoids free-form fragility.
- **Hermetic mode** — `--ignore-user-config` for reproducibility (`CodexSecondOpinionConfig.hermetic=True`).
- **Config-driven** — `codex_second_opinion.{enabled,agents,failure_policy,output_schema_path}` in `harness.yaml` (`src/harness_maker/models.py:440`).
- **Generator-side** — the Codex channel is templatized (`templates/agents/_partials/second_opinion_codex.md.j2`, `codex_permission_line.md.j2`, `codex_tools_bash_suffix.md.j2`) and rendered into target harnesses, not hand-wired.
- **Multi-target** — renders `.codex/`, `.cursor/`, `.claude/`.
- **Mandatory-for-plan-validator** — PLAN-codex-mandatory-second-opinion makes plan-validator MUST reconcile every Codex finding.

The complementary gap: harness-maker has the **engineering/packaging**; the vault skill has a deeper **protocol** (multi-round PIDA debate, a symmetric general-question route, a 4-route taxonomy). Several items below are about porting that protocol depth in.

## Findings (priority-ordered)

### H1 🔴 — Second-opinion is a one-shot reconcile, not a debate protocol
**File:** `src/harness_maker/templates/agents/_partials/second_opinion_codex.md.j2`
**Problem:** The Claude agent ingests Codex findings but keeps its own Claude-derived verdict → **self-adjudication bias remains** (the same model that produced the position decides whether the challenge is "material"). *Codex flagged this about its own integration.*
**Improve:** Import a PIDA-style flow for plan/review — independent Codex finding → Claude rebuttal (KEEP/REFUTE with evidence) → **oracle/test decides, else mark `[unresolved]` and surface**. Do not let Claude silently dismiss a Codex challenge when no oracle exists.

### H2 🔴 — Codex is an additive bolt-on, not a consensus peer
**File:** `src/harness_maker/templates/agents/consensus-arbiter_body.md.j2`
**Problem:** The 2/3 consensus ring is all-Claude; Codex findings sit outside the vote as an advisory second-check. No true mixed-family consensus.
**Improve:** Offer a render mode where the ring is `2 Claude + 1 Codex` with a k-of-3 filter (heterogeneous consensus), distinct from `--deep-validate` (which runs 3 Claude).

### H3 🟠 — Generated-harness quality is judged only by the same model family
**Files:** `src/harness_maker/llm_judge.py`, `.claude/skills/ai-readiness-rubric/SKILL.md`, `.claude/skills/agent-quality-rubric/SKILL.md`
**Problem:** L2 rubric judgment + agent-quality tiering are Anthropic/Claude-only. A harness generated by Claude is then graded by Claude → shared blind spots pass. The generator never gets a heterogeneous read on its own output.
**Improve:** Optional Codex audit pass (strict-schema) over generated `CLAUDE.md`, agents, skills, and rubric YAML; surface disagreements rather than averaging.

### H4 🟠 — `warn-and-proceed` can silently hide a broken Codex integration  *(Codex-only finding)*
**Files:** `src/harness_maker/templates/agents/_partials/second_opinion_codex.md.j2`, `.claude/memory/wiki.md`
**Problem:** Failures degrade to Claude-only; memory already records repeated Codex skip causes (schema mismatch / CLI flag / tool issues). A broken Codex path looks identical to "Codex agreed / nothing to add."
**Improve:** Add a positive smoke check to `/hm:health` — a real `codex exec --sandbox read-only --output-schema …` round-trip reported as explicit pass/fail, so a silently-degraded integration is caught.

### H5 🟡 — Hermetic mode may erase useful project context  *(Codex-only finding)*
**File:** `src/harness_maker/templates/agents/_partials/second_opinion_codex.md.j2`
**Problem:** `--ignore-user-config --ignore-rules` buys reproducibility but drops local `AGENTS.md` / Codex rules that encode real constraints — Codex may flag things the project already decided.
**Improve:** Pass a **curated** context bundle explicitly (PLAN/SPEC, diff, harness-policy excerpts, known invariants) instead of bare hermetic.

### H6 🟠 — No calibration ledger for Codex accuracy over time
**Files:** `second_opinion_codex.md.j2`, `templates/commands/hm/health.md.j2`
**Problem:** Reconciliations are returned in-agent; health decisions log generic remediation choices, not Codex KEEP/REFUTE outcomes vs. ground truth. Codex is trusted at face value forever; no learning loop.
**Improve:** Persist `.claude/observability/codex-second-opinion.jsonl` — `{finding, disposition, oracle_result, later_regression_link}` — to track Codex precision per project and calibrate trust / tune which agents make it mandatory. *(This was the cross-system #1 top pick.)*

### H7 🟠 — Default-off + partial-mandatory under-uses Codex on high-risk paths
**File:** `src/harness_maker/models.py` (`CodexSecondOpinionConfig`, `enabled=False` default; only plan-validator MUST, code-reviewer/consensus-arbiter MAY)
**Problem:** Production / high-blast-radius review+plan can run with no heterogeneous check.
**Improve:** Make Production/high-risk presets default Codex **mandatory** for review + plan, with explicit **skip receipts** (logged reason when skipped) so the absence is auditable.

### H8 🟡 — Codex is review/plan-only; no general-question or handoff routes
**Reference:** vault `.claude/skills/codex-duel/SKILL.md` route table
**Problem:** harness-maker's Codex only attaches to review and plan. It cannot run a symmetric general-question debate (vault Route Q), a diagnosis handoff (Route C), or an implementation handoff (Route D).
**Improve:** Absorb the route taxonomy into the generator so generated harnesses can expose a `/duel`-equivalent (Route Q answer-duel especially — both models answer a plain question independently, then debate, then synthesize with a claim-by-claim reconciliation table).

## Suggested sequencing (for a harness-maker session)

1. **H6 ledger** + **H4 health smoke-test** — cheap, high-leverage observability; makes everything else measurable and catches silent degradation first.
2. **H1 PIDA flow** + **H7 mandatory-on-high-risk** — the protocol-depth core; convert one-shot reconcile into a real debate where it matters most.
3. **H2 heterogeneous consensus** + **H3 generated-harness audit** — structural; Codex becomes a peer and audits the generator's own output.
4. **H5 curated hermetic bundle** + **H8 route taxonomy** — refinements / scope expansion.
