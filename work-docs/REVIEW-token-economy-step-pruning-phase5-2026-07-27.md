# REVIEW — Phase 5: wire the unattributed breakdown into `/hm:metrics`

## What landed

One bullet in `metrics.md.j2` Step 5d, six render-grep assertions, and **AC-011** in both
SPEC files. The fields have shipped since Phase 2; what was missing was any instruction to
render them. Step 5b dumps the whole report JSON into the model's context, so they were
never *dead* — but Step 5d's list is prescriptive, not illustrative: what it enumerates is
what reaches the user's output. `metrics.md.j2` appeared **zero** times in the PLAN before
Phase 5 was added as a review follow-up, so as written no phase would ever have wired it.

## Findings

### F1 — the phase as planned had a gate and no acceptance criterion

Which is the same shape as the defect it fixes: a surface nobody owns. Phase 5 was added
during Phase 2's review with an exit criterion but no AC, so the SPEC tooling
(`find-unbound`, the wrapup binding gate) had nothing to see. **AC-011** now exists in
`SPEC-…machine.yaml` and `SPEC-….md` and is bound to a real test node.

Adding it surfaced a second thing worth knowing: the dual-file contract enforces both a
`### AC-011` prose heading **and** a ≥0.85 title-similarity match between the two files.
The first `mark-tested` attempt failed on the heading, the second on a 0.65 title ratio.
That is the contract working — the machine SPEC cannot drift from the prose one.

### F2 — two of six assertions were vacuous, and one was green before the change

The first mutation run killed 4 of 7. Two survivors were real:

- **M1**: `"unattributed_breakdown" in step_5d` is satisfied by
  `unattributed_breakdown_notes`, because one identifier is a **prefix of the other**.
  The entire bullet could be deleted and the assertion would hold.
- **M7**: the turns/usd check ranged over the whole Step 5d slice, which already contains
  `capped_turns` and a `$` from neighbouring bullets. **This assertion passed before the
  template was touched.** I saw it pass in the RED run, noted it, and moved on — a green
  assertion at RED time is a defect report, not a convenience.

Both are one error: the assertion ranged over more text than the thing it was about.
Recorded as [ADR-021](PLAN-token-economy-step-pruning.md#adr-021); the fix is a bullet-level
extractor with its own non-vacuity control, plus delimited (backticked) matching wherever
one identifier is a prefix of another.

The third survivor (**M5**) was a defective mutant — it replaced only the bullet's first
line, so every other token stayed inside the slice. Identical in shape to Phase 4's M6.
**Two phases running, a mutant that did not reach the artifact was reported as a survivor**;
the check needed is that the mutation actually changes the rendered output.

Second run: **7 / 7 killed, 0 survivors.**

### F3 — the PLAN's stated merge hazard for this phase does not exist

Phase 5's `merge_hazards` said `commands/hm/metrics.md` is regenerated by Phase 4, so
landing later would ship a stale artifact. Checked rather than inherited: `.claude/commands/`
is untracked (0 tracked files), so no rendered command is committed at all; and Phase 4's
hoist touches only the preflight, Gate-0 and stage-summary partials — `metrics.md` is not a
fused command and has none of them. The ordering constraint was real when written and was
made moot by Phase 4's final scope.

### F4 — one drift guard added beyond the exit criterion

The notes have exactly one author, `economics._UNATTRIBUTED_BREAKDOWN_NOTES`. A template
that paraphrased them would go stale the moment that tuple is edited, with nothing
downstream to notice. The test therefore asserts both that the field is *referenced* and
that no note's opening phrase appears inline — imported from the production module, so the
oracle is independent of the template under test.
